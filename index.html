Your API returns 200. Your agent still gets garbage.

driftprobe tests the data your AI agent really receives from APIs and MCP tools. It fails when a source keeps answering while the content quietly degrades.

Every check you have is green.

Schema diff Did the shape change? no field changed ✓ pass
driftprobe Is the data your agent needs still there? 84% of the prices are gone ✕ fail

A person looking at this data would notice the empty column in two seconds. Your agent does not stop. It writes a confident report from what it received, and nobody finds out until a customer does.

It learns the contract from your agent’s real calls.

  1. 1

    Record

    A local proxy sits between your agent and the source. It forwards everything untouched and writes down the shape of each response. Works on HTTP APIs and on MCP tools, including over server-sent events.

    driftprobe record --upstream https://api.example.com
  2. 2

    Learn

    What was observed becomes a small YAML file in your repo. You do not need the provider’s cooperation.

    driftprobe learn --observed .driftprobe/observed.jsonl --out-dir contracts

# contracts/products.yaml
name: products
expect:
  min_items: 25
  fields:
    price:      { type: number, min_coverage: 0.9, min_distinct: 2 }
    updated_at: { type: date, max_age: 3d }
  3. 3

    Check

    Run it in CI or on a schedule. It fails with a plain sentence that names the field, and exit code 1 stops the build.

    $ driftprobe check contracts/*.yaml
GET /products
  x price: only 16% of 50 items carry a value (contract: at least 90%)
  x updated_at: newest value is 289 days old (contract: 3d)

1 contract(s): 0 ok, 1 broken, 0 could not be checked

    Or as a GitHub Action: uses: driftprobe/driftprobe@v0

Shapes, never values.

For each field it keeps how many items carry a value, which types were seen, how many distinct values, and the age of the newest date. The proxy listens on your machine only. Secrets stay in your environment, and a contract only reads variables that start with DRIFTPROBE_, so one you did not write cannot reach the others.

What it does not do. It does not know if a value is true, only if it is there, fresh and varied. Field names and route words are kept, so read a contract before you commit it. It learns what your agent receives: narrowing that to what your agent actually reads is manual for now, with --fields name,price.

How often does this really happen?

I could not find anyone who has measured it. So I am measuring it, on the official MCP registry.

  1. 53,434 servers listed on 31 October 2026
  2. 2,000 remote ones sampled, no credential declared, at most 5 per domain
  3. 1,115 answered with their tool list
  4. 770 declared a read only tool
  5. 415 returned data from a read only call
  6. 100 real lists, across 98 domains, kept for the study

One read only tool on each, twice a day, for 30 days, recording shapes only. Results go out in December whatever they show, including if almost nothing breaks.
